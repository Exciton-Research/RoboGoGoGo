# Development and verification

Run these commands from the repository root unless stated otherwise. Start with
[installation](installation.md) and `bash scripts/setup.sh --dev`.

## Repository map

- `src/robogogogo/demo/`: Panda scene/assets, explicit environment stepping,
  object library, reference controller, recording/replay, HTTP transport, and the
  `PandaPolicy` / `step_policy` boundary. This is the current tabletop workbench.
- `studio/src/demo/`: Panda scene rendering, object/target selection, manual
  controls, and recording/replay UI.

- `src/robogogogo/robot/`: robot identity, geometry, camera mounts, hardware
  calibration/telemetry, actuator catalogs, and command adapter contracts.
- `src/robogogogo/simulation/`: JAX dynamics, kinematics, integration, and numerical
  contact/material primitives. `session.py` owns state advancement and trajectories.
- `src/robogogogo/planning/`: configuration-space, whole-body, and collision planning.
- `src/robogogogo/data/` and `learning/`: aligned episodes, persistence, archive
  readers, and training-input validation.
- `src/robogogogo/runtime/`: shared observation/action contracts, policies,
  supervision, workflow readiness, and command ownership/watchdogs.
- `src/robogogogo/studio/`: HTTP/WebSocket transport, schemas, workspace, and episode
  lifecycle. `server.py` is the launcher.
- `studio/`: Next.js/React UI and Three.js rendering. `studio/out/` and the Python
  `web/` directory are generated by the production build.
- `tests/`: Python regressions, with legacy numerical models under `fixtures/`.
  Those fixtures are not supported product robots or importable product features.
- `docs/validation/`: engineering evidence for specific design revisions.

See [platform layers](platform.md) before adding cross-layer dependencies. Keep
Panda and RG Mobile Duo observations, actions, and archives separate. The Panda
uses MuJoCo and eight absolute targets; the original Studio has a different JAX
model and command convention.
Use minimal fixtures for isolated mathematical regressions.

## Python and frontend editing

The Python installation is editable: source edits apply after server restart.
For frontend hot reload, run two terminals:

```sh
# Terminal 1: Panda API and simulation.
.venv/bin/robogogogo-demo
```

```sh
# Terminal 2: Next.js development server.
npm run dev --prefix studio
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). Next proxies HTTP API requests
to port 8765; the simulation WebSocket connects directly to that Python port.
Both localhost development origins are allowed by the local API. The Panda
workbench uses HTTP; the WebSocket path applies to the earlier Studio. Launch
`robogogogo-studio` instead when developing that workspace.

If Python runs on a different port, configure both paths:

```sh
ROBOGOGOGO_API_URL=http://127.0.0.1:8876 \
NEXT_PUBLIC_ENGINE_WS=ws://127.0.0.1:8876/api/ws \
npm run dev --prefix studio
```

For production-style verification use `npm run build --prefix studio`, restart
Python, and open its port directly. The build generates static pages and copies
them to `src/robogogogo/web/`. Do not commit generated assets. A Python wheel
intended to include Studio must be built after packaging the UI.

## Checks

```sh
python3 scripts/check_publication.py
python3 -m unittest discover -s tests -p test_publication.py
.venv/bin/ruff check src tests examples scripts
.venv/bin/ruff format --check src tests examples scripts
.venv/bin/pytest -q
npm test --prefix studio
npm run format:check --prefix studio
npm run typecheck --prefix studio
npm run build --prefix studio
```

The publication check scans tracked content and embedded ZIP files for personal
paths, recognizable credentials, and unreviewed GitHub repository links. Review
new repository destinations before adding them to the public allowlist in
`scripts/check_publication.py`. Diagnostics withhold matched values. CI runs this
check without installing the simulation dependencies. It checks current files;
it does not inspect or rewrite Git history.

The Python suite enables JAX float64 in `tests/conftest.py`. Cold compilation and
long numerical recovery scenarios can take several minutes; there can be long
pauses between test progress dots. Use targeted suites during iteration:

```sh
.venv/bin/pytest -q tests/test_mobile_*.py tests/test_whole_body.py tests/test_robot_product.py
.venv/bin/pytest -q tests/test_vla.py tests/test_server.py tests/test_workflow_layers.py
.venv/bin/pytest -q tests/test_execution.py tests/test_execution_api.py
```

Frontend tests use Node's test runner and TypeScript stripping, hence Node 22.6+.
They cover rendering contracts without requiring WebGL. The screenshot workflow
below exercises the real browser/WebGL and API capture/save/validate path.

Format only changed Python files with `.venv/bin/ruff format <paths>`. Use
`npm run format --prefix studio` for frontend sources. Dependency changes should
update `studio/package.json` and `studio/package-lock.json` together; normal setup
uses `npm ci`. CI runs Python checks and the installer on macOS and Linux, plus
frontend tests, formatting, type checking, and production export.

Electrical routing remains deferred for the current robot geometry. Tests retain
legacy route candidates and verify that infeasible paths are rejected; they do
not assert a released wiring design. Removed clamp geometry is replaced by
explicit mathematical fixtures when testing attachment-contact rules. Similarly,
collision counterexamples must match the current geometry: keep clear endpoints,
an actually blocked swept path, and the expected torso/opposite-arm collision
coverage when updating a robot revision. Do not remove guards to repair a stale
test pose.

## Regenerate documentation screenshots

The checked-in screenshots are real Studio captures at a 1600 × 1100 viewport
(full-page images may be taller). The script checks browser page errors and
records one zero-delta simulation transition, saves it, and validates the archive.
**Use a disposable project directory:** the script starts a new episode and saves
it, so it must not run against a workspace containing unsaved work.

After installing development dependencies, install the browser once:

```sh
npm exec --prefix studio -- playwright install chromium
```

Linux CI/headless machines may need browser system libraries; Playwright can
install them with `playwright install --with-deps chromium` when authorized.
This is only for screenshot tooling; ordinary Studio users render in their own
browser and do not need Playwright's Chromium.

Build the current UI and start a separate server:

```sh
npm run build --prefix studio
.venv/bin/robogogogo-studio --port 8876 --test-execution \
  --projects /tmp/robogogogo-doc-screenshots
```

In another terminal, wait for Python startup, then run:

```sh
STUDIO_URL=http://127.0.0.1:8876 npm run screenshots --prefix studio
```

If you already have Google Chrome installed, you can use it instead of installing
Chromium by adding `BROWSER_CHANNEL=chrome` to that command. The script writes
`docs/images/simulation.png`, `episode-setup.png`, `episode.png`, `workflow.png`,
`hardware.png`, and `command-test.png`. Inspect all six images before committing them. It leaves
hardware disconnected and never arms the command test backend. Ctrl+C stops the
documentation server when finished.

## Data contracts and API exploration

Interactive API documentation is at [http://127.0.0.1:8765/docs](http://127.0.0.1:8765/docs)
while Python is running. OpenAPI is at `/openapi.json`. Studio's local origin and
host checks apply to HTTP and WebSocket requests; keep the API on loopback.

To inspect a numerical export without unpickling:

```python
import json
import numpy as np

with np.load("/tmp/mobile-run.npz", allow_pickle=False) as run:
    metadata = json.loads(str(run["metadata"]))
    print(metadata["robot"], run["q"].shape, run["time"][-1])
```

Use `inspect_dataset` for current training-input validation and `iter_transitions`
to read aligned observations/actions. Validate before downstream preprocessing.
Do not relabel historical robot revisions or simulation data as measured hardware
demonstrations. See the [walkthrough](getting-started.md) for the archive layout.

## Prepare a release

Original project materials use Apache-2.0. Preserve `LICENSE`, `NOTICE`, and
`THIRD_PARTY_NOTICES.md` in distributions. The latter contains the upstream texts
for Studio's JavaScript and fonts, including Next.js's vendored notices. Python
dependencies remain separately installed distributions with their own licenses;
do not redistribute downloaded vendor CAD under the project's license.

After changing npm dependencies, use `npm ci --prefix studio`, run
`npm run notices --prefix studio`, review the generated changes, and commit the
lockfile and notices together. `npm run build --prefix studio` checks that the
committed notices match the installed dependencies and copies all three legal
files to both the static export and Python's packaged UI.

Build and inspect a release locally (requires the `dev` extra):

```sh
npm ci --prefix studio
npm run build --prefix studio
.venv/bin/python -m build
.venv/bin/python scripts/check_release.py
```

The check inspects the wheel and source archive without extracting them. It
requires the project license metadata, exact legal files, built Studio pages,
and bundled fonts, and rejects local credentials, recordings, caches, and
dependency directories. It does not upload a release or change repository
visibility. CI runs this same artifact check on Linux; the setup checks also
cover macOS.

Before publication, review the [security reporting instructions](../SECURITY.md)
and make sure a private reporting channel is actually available in the repository
settings. Confirm ownership and attribution of any newly added assets. Existing
simulation and hardware limitations remain applicable to an open-source release.
